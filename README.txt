ZCOREBIT MEDIA — WEBSITE README
================================

WHAT THIS IS
------------
A static, hand-built brand site. There is no CMS and no server-side
code — every page is plain HTML/CSS/JS, generated by a small local
build script so the header and footer only have to be written once.

HOW THE SITE IS BUILT
----------------------
Source of truth:
  build/routes.mjs      One entry per page: URL, output file, <title>,
                         meta description, OG image, sitemap priority.
  build/partials.mjs    The header, mobile menu, and footer — written
                         ONCE here and stamped onto every page.
  content/<page>.html   Just the page-specific content (what's inside
                         <main>) for each page.
  site.config.json      Site name + production domain.

Generated output (do not hand-edit — re-run the build instead):
  index.html, about/index.html, services/index.html, work/index.html,
  contact/index.html, privacy/index.html, terms/index.html, 404.html,
  sitemap.xml, robots.txt

TO MAKE A CONTENT CHANGE
-------------------------
1. Edit the relevant file in content/ (or build/partials.mjs for
   something in the header/footer that appears on every page).
2. From the project root, run:
       node build/build.mjs
3. Commit the changed source files AND the regenerated output files.

TO ADD A NEW PAGE
-------------------
1. Add a fragment at content/<slug>.html.
2. Add a matching entry to build/routes.mjs (URL, output path, meta).
3. Run `node build/build.mjs`. The new page is automatically added to
   the header nav (if navLabel is set) and to sitemap.xml.

CLEAN URLS
----------
Every page lives at a folder with an index.html inside it
(e.g. about/index.html), so /about resolves directly with a 200 —
no redirect involved. The only 301 redirects on the site are for the
old *.html links from before this rebuild (e.g. /about.html ->
/about), kept solely so old bookmarks/backlinks still resolve; new
links should always use the clean, extensionless path.

Primary hosting target: Apache / cPanel — see .htaccess in the site
root, which handles the clean-URL rewriting and those legacy 301s.
_redirects (Netlify) and vercel.json (Vercel) are also included and
kept in sync in case the site is ever moved to either platform.

SEO FILES
---------
  robots.txt    Regenerated by the build script; points crawlers at
                sitemap.xml. Edit the template in build/build.mjs if
                the crawl rules ever need to change.
  sitemap.xml   Regenerated by the build script from build/routes.mjs
                every time you run `node build/build.mjs` — it always
                reflects the current page list, so it never goes stale.

ANALYTICS / GA4 / GOOGLE TAG MANAGER
-------------------------------------
Every conversion-relevant element (WhatsApp buttons, Call buttons,
email links, the map card, nav CTAs, service links, etc.) has a
unique, stable id built from its purpose + the page it's on, e.g.
  whatsapp-cta-home, whatsapp-cta-contact, contact-chip-email-contact
This means a GTM trigger can target "Click ID equals
whatsapp-cta-contact" directly, without needing to also match on
Page Path, and won't accidentally also fire for the same button on
another page. No GTM container is wired in yet — when one exists,
add the standard GTM snippet to build/partials.mjs (renderHead) so it
lands on every page at once.

IMAGES & VIDEO
---------------
All photography and the hero footage are hosted locally under
/assets (nothing is pulled from Unsplash or any other third party at
runtime) and compressed to WebP (images) / H.264+VP9 (video). Source
files are pre-sized per usage (e.g. portfolio cards ship 800w/1200w
srcset pairs) rather than shipping one oversized master everywhere.

DOMAIN
------
site.config.json currently points at https://media.zcorebit.com. If
that changes, update it there and re-run the build — canonical URLs,
OG tags, and sitemap.xml all derive from that one value.
